# 02.9 — Regras do Music Engine

## Objetivo
Consolidar as regras que transformam intenções de edição em um Music Model musicalmente consistente.

O Music Engine é o núcleo responsável pela lógica musical. A interface solicita operações; ela não decide as regras.

## Operações principais

```text
createScore()
insertNote()
insertRest()
insertChord()
deleteEvent()
changeDuration()
changeClef()
changeTimeSignature()
addAccidental()
addVoice()
addTie()
addArticulation()
```

## Inserção de nota
Fluxo:

```text
Input
  ↓
intenção do usuário
  ↓
Music Engine
  ↓
validação temporal
  ↓
Music Model
  ↓
Renderer
```

## Validação temporal
Ao inserir um evento:
1. identificar compasso e voz;
2. determinar posição temporal;
3. obter duração exata;
4. verificar capacidade restante;
5. aceitar, ajustar ou rejeitar conforme regra definida;
6. atualizar posição do cursor.

O Engine nunca deve permitir silenciosamente um estado musical impossível.

## Cursor inteligente
A Nota Pronta mantém um cursor lógico independente do cursor visual.

```text
cursorPosition = posição temporal do próximo evento
```

Após inserir uma nota válida:

```text
cursorPosition += duration
```

Se o compasso atingir sua capacidade:

```text
cursor → próximo compasso
```

## Overflow
Quando a duração exceder a capacidade restante, o Engine deve preservar a intenção musical por meio de uma operação determinística.

Estratégia inicial recomendada:
- se a duração puder ser representada por divisão notacional válida, dividir o evento entre compassos;
- caso contrário, rejeitar a operação com feedback claro;
- nunca truncar silenciosamente a nota.

Isso prepara o sistema para ligaduras entre compassos.

## Subdivisão e notação
A capacidade temporal não determina sozinha a grafia ideal. O Engine deve distinguir:

```text
quantidade de tempo
≠
grafia rítmica
≠
grupamento visual
```

A camada de notação poderá decidir como uma duração é segmentada para apresentação, respeitando o contexto métrico.

## Altura
O Engine trabalha com pitch estruturado:

```text
step + alter + octave
```

Não deve armazenar somente a coordenada gráfica ou somente um número MIDI.

## Clave
A clave determina interpretação gráfica, não altera o pitch do evento.

## Acidentes
O Engine mantém a diferença entre:
- acidente explícito;
- alteração efetiva para reprodução;
- contexto notacional.

## Vozes
Cada voz possui sua linha temporal independente. Eventos simultâneos em vozes diferentes não devem ser fundidos em acorde automaticamente.

## Undo/Redo
Toda operação mutável deve ser modelada como uma ação reversível.

Conceitualmente:

```text
Command
  ├── execute()
  └── undo()
```

Isso permitirá histórico, atalhos e colaboração futura sem reescrever o núcleo.

## Imutabilidade e previsibilidade
Sempre que possível, operações do Engine devem produzir um novo estado ou uma mudança claramente delimitada. A UI não deve alterar diretamente objetos musicais internos.

## Entrada multiplataforma
Todos os meios de entrada devem convergir para operações do Engine:

```text
Mouse  ─┐
Touch  ─┤
Keyboard├──> Music Engine
MIDI   ─┤
Handwriting ┘
```

Isso garante que a mesma regra seja aplicada independentemente do dispositivo.

## Reprodução
O Playback Engine deve consumir o Music Model validado. Ele não deve inferir regras musicais a partir do SVG ou da tela.

## Renderer
O Renderer recebe o estado musical e produz a representação gráfica. Ele não deve ser a fonte de verdade.

## Critérios de aceitação
- Toda alteração musical passa pelo Music Engine.
- Nenhuma entrada de usuário escreve diretamente no SVG como fonte de verdade.
- Eventos inválidos não entram no Music Model.
- Posição, duração e andamento continuam separados.
- Pitch escrito permanece independente da clave.
- Vozes preservam independência temporal.
- Undo/redo pode representar operações do domínio.
- Mouse, toque, teclado e futuras entradas usam as mesmas operações.

## Decisões consolidadas
- `MUSIC-025`: Music Engine é a autoridade das regras musicais.
- `MUSIC-026`: Renderer não é fonte de verdade do documento.
- `MUSIC-027`: Playback consome o Music Model, não a representação gráfica.
- `MUSIC-028`: entradas distintas convergem para as mesmas operações de domínio.
- `MUSIC-029`: operações mutáveis devem ser compatíveis com histórico reversível.
