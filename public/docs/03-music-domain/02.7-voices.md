# 02.7 — Vozes

## Objetivo
Definir como eventos simultâneos coexistem dentro de uma mesma pauta sem confundir simultaneidade com acorde.

## Por que vozes existem
Uma pauta pode conter linhas rítmicas independentes simultâneas.

```text
Pauta
├── Voz 1 → ♩ ♪ ♪ ♩
└── Voz 2 → ♪ ♪ ♩ ♩
```

Isso é diferente de um acorde, no qual várias alturas pertencem ao mesmo evento musical.

## Distinção fundamental

**Acorde**:
```text
1 evento
└── várias alturas
```

**Vozes**:
```text
vários eventos
└── posições temporais potencialmente simultâneas
```

## Modelo

```json
{
  "id": "voice-1",
  "index": 1,
  "events": []
}
```

O compasso contém uma ou mais vozes:

```text
Compasso
├── Voz 1
│    ├── Evento
│    └── Evento
└── Voz 2
     ├── Evento
     └── Evento
```

## Posição temporal
Cada evento mantém sua própria posição e duração. A capacidade do compasso deve ser validada por voz, quando a notação estiver em múltiplas vozes.

Isso evita tratar a soma das durações das vozes como se fosse uma única linha temporal.

## Voz padrão
No MVP, toda pauta deve iniciar com uma voz única (`voice 1`). A estrutura deve permitir adicionar outras vozes sem migração conceitual do modelo.

## Interação
A ferramenta Nota Pronta deve operar sobre uma voz ativa.

Futuro:
- seletor de voz;
- entrada por teclado;
- edição de uma voz sem destruir outra;
- reprodução polifônica.

## Critérios de aceitação
- Uma pauta pode conter pelo menos uma voz.
- Vozes têm eventos independentes.
- Acordes não são tratados como vozes.
- O modelo suporta simultaneidade sem duplicar a pauta.
- O Music Engine pode validar duração por voz.

## Decisões
- `MUSIC-019`: voz é uma camada temporal independente dentro da pauta.
- `MUSIC-020`: acorde e vozes são conceitos distintos.
- `MUSIC-021`: o MVP começa com uma voz, mas o modelo nasce preparado para polifonia.
