# 02.6 — Acidentes

## Objetivo
Definir a representação dos acidentes e separar alteração de altura, grafia e efeito contextual dentro do compasso.

## Tipos
O modelo inicial deve suportar:
- natural;
- sustenido;
- bemol;
- duplo sustenido;
- duplo bemol.

Estrutura:

```json
{
  "pitchClass": "C",
  "alter": 1
}
```

Convenção:
- `0` = natural;
- `1` = sustenido;
- `-1` = bemol;
- `2` = duplo sustenido;
- `-2` = duplo bemol.

## Pitch escrito × efeito sonoro
O acidente escrito faz parte da identidade notacional da nota. O Music Model deve preservar a grafia escolhida mesmo quando duas grafias possuem o mesmo resultado cromático.

Exemplo:

```text
C# ≠ Db
```

Embora possam corresponder à mesma classe cromática em afinação temperada, são grafias diferentes e podem ter funções harmônicas diferentes.

## Acidente explícito
Uma nota pode carregar um acidente explícito:

```json
{
  "type": "note",
  "pitch": {
    "step": "C",
    "alter": 1,
    "octave": 4
  }
}
```

## Acidente implícito/contextual
O sistema deverá manter futuramente um estado de alterações vigentes por compasso e voz. Esse estado é uma regra de notação, não deve ser gravado como simples mutação permanente do pitch.

Conceitualmente:

```text
Pitch escrito
      +
Acidente explícito
      +
Contexto do compasso/voz
      ↓
altura efetiva para reprodução
```

## Regras importantes
- O acidente explícito pertence ao evento.
- A validade contextual do acidente depende de voz, compasso e convenções de notação adotadas.
- Alterar a clave não altera acidentes.
- Alterar a tonalidade futuramente não deve destruir a grafia original sem uma operação explícita de reescrita.

## Reprodução
O áudio pode usar uma altura cromática efetiva derivada do pitch. O sistema de áudio não deve decidir qual acidente desenhar.

## Critérios de aceitação
- Suportar pelo menos cinco tipos de alteração.
- Preservar enarmonia.
- Separar acidente explícito de estado contextual.
- Permitir derivar altura de reprodução sem perder a representação escrita.

## Decisões
- `MUSIC-016`: acidentes fazem parte da representação notacional da nota.
- `MUSIC-017`: enarmonia deve ser preservada no Music Model.
- `MUSIC-018`: o estado contextual de acidentes será calculado pelo Music Engine.
